# Проект «Будущее 2.0» — Архитектура данных и трансформация IT-ландшафта

## Контекст
Компания «Будущее 2.0» — медицинский стартап, выросший в экосистему, включающую:
- Клиники и медицинские услуги.
- Финтех-направление (приобретён банк).
- ИИ-сервисы для диагностики и лечения.
- Планы по интеграции фармацевтических компаний и производителей медоборудования.

Текущий ландшафт:
- **DWH** на Microsoft SQL Server 2008 (сотни ТБ), содержит все корпоративные данные: клиенты, медкарты, финансы, счета, кредиты, персонал, инвентаризация и т.д.
- **BI**: Power BI с множеством кастомизаций поверх DWH.
- **Интерфейс оператора**: PowerBuilder.
- **Интеграции**: ESB на Apache Camel.
- **ИИ-сервисы**: Python.
- **Финтех-сервисы**: Golang и Java.

Проблемы:
- Отчётность строится слишком долго (часы), time-to-market падает.
- Множество трансформаций, нагрузка на DWH.
- Жёсткая связанность, сложность добавления новых направлений.

## Бизнес-цели
1. **Промежуточные (2 месяца):**
   - Архитектурное решение согласовано.
   - Определены границы доменов и их связи.
   - В доменах запланированы проекты по созданию «витрины данных» (портала самообслуживания).

2. **Финальные (1 год):**
   - Реализован портал самообслуживания для бизнес-пользователей (без медицинских карт и историй болезней).
   - Новая архитектура работает в доменах, легаси временно сохраняется.

3. **Долгосрочные (3 года):**
   - Масштабирование по продуктам, географии и данным.
   - Переход к событийной платформе со слабой связанностью, реактивным потокам.
   - Отказ от синхронных интеграций через Camel и DWH, использование их только как мостов на время миграции.

## Этапы трансформации
- **Этап 1 (0–6 мес)**: Пилот в 1–2 доменах (финансовые расчёты или пациентский поток), ввод событий, DLQ, каталог схем.
- **Этап 2 (6–18 мес)**: Расширение на критические домены, потоковые витрины, антикоррупционные слои для интеграций через Camel и DWH.
- **Этап 3 (18–36 мес)**: Отказ от точечных синхронных интеграций, переход к доменной аналитике на потоках.

## Ограничения и требования
- Медицинские карты и исследования **не** используются в аналитике (витрина данных).
- Соблюдение регуляторных требований (медицина + финансы).
- Информационная безопасность, геораспределённость, отказоустойчивость.
- Переход в облако (гибкость, масштабирование).

## Задачи финального задания
1. **Task1Advanced** – переиспользуемый модуль Terraform для облачной инфраструктуры.
2. **Task2Advanced** – Terraform-код для развёртывания компонентов.
3. **Task3Advanced** – C4-диаграмма, карта рисков, план управления.
4. **Task4Advanced** – схема bounded contexts, Event Storming, аргументация.
5. **Task5Advanced** – расширенный техрадар, TCO-анализ, роадмап.

Все решения будут приниматься в контексте описанных бизнес-целей, этапов и ограничений.
